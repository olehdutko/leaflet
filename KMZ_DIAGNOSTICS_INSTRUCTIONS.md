# Інструкції для діагностики проблеми з KMZ імпортом

## Проблема
Об'єкти імпортуються з назвами "[без назви]" замість реальних назв з KMZ файлу.

## Діагностика

### Крок 1: Аналіз KML структури
1. Відкрийте `http://localhost:8001/test-kmz-simple.html`
2. Виберіть KMZ файл
3. Натисніть кнопку **"Аналізувати KML"**
4. Відкрийте консоль браузера (F12)
5. Подивіться на логи аналізу структури KML файлу

### Крок 2: Перевірка логів аналізу
В консолі повинні з'явитися логи:
```
=== АНАЛІЗ KML ФАЙЛУ БЕЗ ІМПОРТУ ===
Знайдено KML файл: [назва файлу]
KML контент (перші 1000 символів): [контент]
=== АНАЛІЗ СТРУКТУРИ KML ФАЙЛУ ===
Загальна кількість Placemark елементів: [кількість]

--- Placemark 1 ---
Елементи в Placemark:
- name: [true/false] [назва або undefined]
- description: [true/false] [опис]
- ExtendedData: [true/false]
- Point: [true/false]
- LineString: [true/false]
- Polygon: [true/false]
```

### Крок 3: Аналіз результатів
Перевірте в логах:

1. **Чи є тег `<name>` в Placemark:**
   - Якщо `name: true` - назва повинна парситися
   - Якщо `name: false` - назва відсутня в тегу name

2. **Чи є ExtendedData:**
   - Якщо `ExtendedData: true` - перевірте Data елементи
   - Шукайте Data з атрибутом `name="name"` або подібним

3. **Чи є опис:**
   - Якщо `description: true` - перевірте вміст опису
   - Можливо назва знаходиться в описі

### Крок 4: Імпорт з діагностикою
1. Натисніть **"Імпортувати KMZ"**
2. Подивіться на логи парсингу в консолі:
   ```
   Парсимо placemark: {
     name: [назва або порожній рядок],
     description: [опис],
     hasNameElement: [true/false],
     hasExtendedData: [true/false],
     hasDescription: [true/false],
     placemarkHTML: [HTML структура]
   }
   ```

### Крок 5: Аналіз проблеми
На основі логів визначте:

1. **Якщо назви відсутні в тегу `<name>`:**
   - Перевірте ExtendedData
   - Перевірте опис
   - Перевірте інші місця в KML

2. **Якщо назви є в тегу `<name>`:**
   - Перевірте, чи правильно парситься текст
   - Перевірте, чи немає HTML тегів в назві

3. **Якщо назви в ExtendedData:**
   - Перевірте структуру Data елементів
   - Знайдіть правильний атрибут name

## Типові проблеми та рішення

### Проблема 1: Назви в ExtendedData
```xml
<ExtendedData>
  <Data name="name">
    <value>Назва об'єкта</value>
  </Data>
</ExtendedData>
```
**Рішення:** Додано парсинг ExtendedData в код.

### Проблема 2: Назви в описі
```xml
<description>Назва об'єкта: Опис об'єкта</description>
```
**Рішення:** Додано витягування назви з початку опису.

### Проблема 3: Назви в SimpleData
```xml
<SimpleData name="name">Назва об'єкта</SimpleData>
```
**Рішення:** Додано парсинг SimpleData елементів.

### Проблема 4: Назви в інших місцях
```xml
<Placemark>
  <SomeElement>Назва об'єкта</SomeElement>
</Placemark>
```
**Рішення:** Додано пошук в усіх дочірніх елементах.

## Додаткові функції діагностики

### В консолі браузера:
```javascript
// Перевірити localStorage
checkLocalStorage()

// Очистити localStorage
clearLocalStorage()

// Аналізувати поточний KML файл
analyzeCurrentKml()
```

### Аналіз структури KML:
Кнопка **"Аналізувати KML"** показує:
- Загальну кількість Placemark елементів
- Структуру перших 5 Placemark елементів
- Наявність різних типів елементів
- Вміст ExtendedData
- Повну HTML структуру першого Placemark

## Очікуваний результат діагностики

Після правильної діагностики:
- ✅ Визначено, де зберігаються назви в KML файлі
- ✅ Оновлено код парсингу для правильного витягування назв
- ✅ Об'єкти імпортуються з реальними назвами
- ✅ Назви зберігаються в localStorage
- ✅ Назви відновлюються після перезавантаження сторінки
