# Інструкції для спрощеного тесту KMZ

## Проблема
Попередній тестовий файл містив помилки в консолі через залежності від основної аплікації.

## Рішення
Створено спрощений тестовий файл без проблемних залежностей.

## Використання

### Крок 1: Відкрийте спрощений тестовий файл
```
test-kmz-simple-debug.html
```

### Крок 2: Перевірте консоль
Відкрийте Developer Tools (F12) і перевірте, що немає помилок. Ви повинні побачити:
```
Простий тестовий скрипт діагностики KMZ властивостей завантажено
Карта ініціалізована
Тестовий файл готовий до використання
```

### Крок 3: Імпортуйте KMZ файл
1. Натисніть кнопку "Вибрати файл" і виберіть KMZ файл
2. Натисніть кнопку "Імпортувати KMZ"
3. Дочекайтеся завершення імпорту

### Крок 4: Використайте функції діагностики
Натисніть кнопки в правому верхньому куті:

- **"Діагностика об'єктів"** - перевіряє об'єкти в пам'яті
- **"Діагностика localStorage"** - перевіряє збережені дані
- **"Примусове збереження"** - зберігає дані в localStorage
- **"Створити тестовий об'єкт"** - створює тестовий об'єкт для перевірки

## Очікувані результати

### При успішному імпорті ви повинні побачити:
```

Знайдено KML файл: [назва файлу]
Назва шару: [назва шару]
```

## Якщо виникають проблеми

### Проблема: Properties порожні
```
⚠️ ПРОБЛЕМА: Properties порожні!
```

**Рішення**: Перевірте, чи правильно парситься KML файл.

### Проблема: feature.properties порожній, але layer.properties має дані
```
⚠️ ПРОБЛЕМА: feature.properties порожній, але layer.properties має дані!
```

**Рішення**: Проблема в копіюванні властивостей з `layer.properties` до `layer.feature.properties`.

## Додаткові функції в консолі

В консолі браузера доступні функції:
- `debugObjects()` - діагностика об'єктів
- `debugStorage()` - діагностика localStorage
- `forceSave()` - примусове збереження
- `createTestObject()` - створення тестового об'єкта
- `importKmz()` - імпорт KMZ файлу

## Переваги спрощеного тесту

1. **Немає залежностей** - не використовує проблемні бібліотеки
2. **Простота** - мінімальний код для тестування
3. **Детальне логування** - повна діагностика процесу
4. **Інтерактивність** - кнопки для різних тестів
5. **Візуалізація** - об'єкти відображаються на карті

## Наступні кроки

Після успішного тестування в спрощеному файлі:
1. Порівняйте результати з основною аплікацією
2. Визначте, де саме виникає проблема
3. Застосуйте виправлення до основної аплікації
