# Правила проекту Lefleat

## Структура файлів

### index.js/index.ts
- **В index.js НЕ повинно бути ніякого JS коду**
- **Тільки імпорти та мінімальна ініціалізація**
- Всі функції та логіка повинні бути в окремих модулях
- index.js служить як точка входу в додаток

### Модульна структура
- Кожен функціональний блок повинен бути в окремому файлі
- Використовувати ES6 модулі (import/export)
- Уникати дублювання коду між файлами

### Найменування файлів
- Використовувати camelCase для назв файлів
- Розширення `.ts` для TypeScript файлів
- Розширення `.js` для скомпільованих файлів

### Імпорти
- Групувати імпорти за типом (вбудовані, зовнішні, внутрішні)
- Використовувати відносні шляхи для внутрішніх імпортів
- Уникати циклічних залежностей

## Код стайл

### TypeScript
- Використовувати строгу типізацію
- Уникати `any` типу, де це можливо
- Використовувати інтерфейси для об'єктів

### Коментарі
- Використовувати українську мову для коментарів
- Документувати складні функції
- Пояснювати неочевидну логіку

### Обробка помилок
- Використовувати try-catch блоки
- Логувати помилки в консоль
- Надавати зрозумілі повідомлення користувачу

## Дебагінг

### Логи
- Використовувати префікси для логів (🚀, ⚠️, ❌, ✅)
- Групувати логи за функціональністю
- Уникати зайвих логів в продакшн

### Дебаг файли
- Дебаг файли повинні бути в окремій папці `del/`
- Не включати дебаг файли в основну логіку
- Використовувати префікс `debug-` для дебаг файлів

## Збереження даних

### localStorage
- Використовувати префікс `lefleat_` для ключів
- Валідувати дані перед збереженням
- Обробляти помилки збереження

### Експорт/Імпорт
- Підтримувати формати JSON, GeoJSON, KMZ
- Валідувати імпортовані дані
- Надавати зворотну сумісність

## UI/UX

### Модальні вікна
- Використовувати семантичну розмітку
- Підтримувати закриття через Escape
- Надавати зворотній зв'язок користувачу

### Адаптивність
- Підтримувати різні розміри екрану
- Використовувати CSS Grid/Flexbox
- Тестувати на різних пристроях

## Безпека

### Валідація
- Валідувати всі вхідні дані
- Санитизувати HTML контент
- Перевіряти типи файлів

### XSS захист
- Не використовувати innerHTML без санітизації
- Використовувати textContent де можливо
- Екранувати користувацький контент
